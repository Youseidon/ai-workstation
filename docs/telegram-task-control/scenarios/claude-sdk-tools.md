# Scenario table: Claude Host-access defect, typed SDK tools

Slice: fix the Claude Host-access defect with typed in-process Agent SDK tools (`get_context`, `post_remark`, `post_status`).
Specification: [engineering plan step 7a, "Defects found during L1"](../engineering-plan.md), [harness plan sections 4.3, 5, 10.4 and 12](../../e2e-harness-plan.md).
Written by the test-design pass from documents and existing public interfaces only (HTTP Progress API in `server/src/index.ts`, `workspaces.addAgentRemark` / `updateAgentStatus` / `authorizeAgentRun`, `runContexts`, `savedPromptExecuteReachabilityProblem`, `RunRole` in `shared/src/index.ts`, and their existing tests).

ID legend used in Covers:
`7a` is the step 7a defect and its fix design bullets (`7a-tools`, `7a-rules`, `7a-shared`, `7a-prompt`, `7a-perm`, `7a-others`, `7a-zod`).
`E2E-4.3` and `E2E-10.4` are the harness plan's fake-provider and real-provider decisions.
`RTC-20`, `H-L1-xx` and `B05` come from the engineering plan, human-verification checklist and user flows.

Tier notes:
The tool path is in-process and cannot be emulated by the fake provider CLI (E2E-4.3), so tool behaviour is T0 against the tool handlers with an isolated database, and end to end is T3 with real Claude.
T1 fake rows cover only the other providers' paths, which this slice must leave unchanged.
"Same as HTTP" below means the same stable error code and HTTP-equivalent status that the existing endpoint returns for the same input.
